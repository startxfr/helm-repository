# ![cluster-grafana](https://helm-repository.readthedocs.io/en/latest/img/cluster-grafana.svg "Cluster Chart : Grafana") Cluster Chart : Grafana
[![Artifacthub](https://img.shields.io/badge/ArtifactHub-STARTX_cluster--grafana-8A2BE2.svg)](https://artifacthub.io/packages/search?ts_query_web=cluster+grafana+startx)

This helm chart is used to deploy Grafana managed by the community `grafana-operator` (Grafana Labs). It installs the
operator, a `Grafana` instance (API `grafana.integreatly.org/v1beta1`) exposed by an OpenShift `Route`, and
`GrafanaDatasource` and `GrafanaDashboard` objects.

Grafana works on its own with a local admin account. It can also authenticate its users with OpenID Connect, and read
the Grafana role from the claims of the user. The provider is either a realm of the Red Hat build of Keycloak, such as
the one deployed by [cluster-rhbk](https://helm-repository.readthedocs.io/en/latest/charts/cluster-rhbk), or any other
OpenID Connect provider with explicit endpoint URLs. Secrets are rendered from the values, or sourced from an external
store with the External Secrets Operator.

This chart is part of the [cluster-xxx startx helm chart series](https://helm-repository.readthedocs.io#cluster-helm-charts) that doesn't necessarily deploy pods but rather represent a cluster configuration state orchestrated by gitops tools like ArgoCD.

## Requirements and guidelines

Read the [startx helm-repository homepage](https://helm-repository.readthedocs.io) for
more information on how to use these resources.

| Requirement | Detail |
| --- | --- |
| OpenShift 4.17+ (Kubernetes 1.30+) | `kubeVersion` of the chart, tested on OpenShift 4.22 |
| grafana-operator 5.25 | `community-operators` catalog (provider Grafana Labs, not supported by Red Hat), package `grafana-operator`, channel `v5`. Installed by the `operator` sub-chart in the namespace of the instance (OwnNamespace). There is no Red Hat or certified Grafana operator. The Red Hat supported alternative for dashboards is the Cluster Observability Operator (Perses) |
| Grafana version | Pinned with `grafana.version` (default `13.1.3`, the default of the 5.25 operator), so an operator upgrade does not change the Grafana version |
| FIPS | Grafana and the grafana-operator are not FIPS validated. They run on a FIPS enabled cluster, but their cryptography is not FIPS compliant |
| OpenID Connect | A confidential client in a Keycloak realm, such as the startx realm of `cluster-rhbk` with its `values-startx_noinfra-grafana.yaml` values, or in any other OpenID Connect provider. Grafana calls the token and userinfo endpoints from its pod, so it must trust the CA of their certificate (`oidc.ca`) |
| OpenShift OAuth | With `oauthProxy.enabled`, the sign in goes through the OpenShift OAuth server (federated to your identity provider) and the oauth-proxy image of the `openshift` ImageStream. The cookie secret Secret is expected from Vault/External Secrets or from `oauthProxy.cookieSecret.value` |
| Secrets | Admin password and client secret are expected as [Argo CD Vault Plugin](https://argocd-vault-plugin.readthedocs.io/) placeholders (`<path:kv/data/...#key>`), from a values file kept out of Git, or from the External Secrets Operator (`externalSecret.enabled`). The `startx_noinfra-rhbk` values file only carries a demo client secret |

## Deploy this helm chart on openshift

### 1. Connect to your Openshift cluster

```bash
oc login -t <token> <cluster-url>
```

### 2. Install the repository

```bash
helm repo add startx https://helm-repository.readthedocs.io/en/latest/repos/stable/
```

### 3. Get information about this chart

```bash
helm show chart startx/cluster-grafana
```

### 4. Install this chart

```bash
helm install cluster-grafana startx/cluster-grafana
```

## Default values

Complete deployment of a project with the following characteristics, using the `values-startx.yaml` values :

- 1 **namespace:** named **default-grafana** without constraints
- 1 **operator:** named **grafana-operator** configured with
  - The **v5** channel of the community catalog, manual install plan approval
  - The **v5.25.0** version
  - Deployed under the **default-grafana** project (OwnNamespace OperatorGroup)
- 1 **grafana:** named **startx**, Grafana **13.1.3**, local admin account generated by the operator
- 1 **route:** named **startx-route** (managed by the operator) with edge TLS termination and a generated host
- 1 **dashboard:** named **startx-welcome**

```bash
# Create the project
helm install cluster-grafana-project startx/cluster-grafana -f https://raw.githubusercontent.com/startxfr/helm-repository/master/charts/cluster-grafana/values-startx.yaml --set project.enabled=true
# Deploy the grafana operator
helm install cluster-grafana-operator startx/cluster-grafana -f https://raw.githubusercontent.com/startxfr/helm-repository/master/charts/cluster-grafana/values-startx.yaml --set operator.enabled=true && sleep 30
# Approve the first install plan (manual approval)
oc patch installplan $(oc get installplan -n default-grafana -o jsonpath='{.items[0].metadata.name}') -n default-grafana --type merge -p '{"spec":{"approved":true}}'
# Deploy the grafana instance, its route and the startx dashboard
helm install cluster-grafana-instance startx/cluster-grafana -f https://raw.githubusercontent.com/startxfr/helm-repository/master/charts/cluster-grafana/values-startx.yaml --set grafana.enabled=true,route.enabled=true,grafana_datasources.enabled=true,grafana_dashboards.enabled=true
```

- **startx_noinfra-rhbk** : the same, plus the OpenID Connect authentication against the startx realm of `cluster-rhbk` (`values-startx_noinfra-grafana.yaml`), the cluster trusted CA bundle and a demo client secret (see [values-startx_noinfra-rhbk.yaml](https://raw.githubusercontent.com/startxfr/helm-repository/master/charts/cluster-grafana/values-startx_noinfra-rhbk.yaml))

Replace the secret store name first. It is checked with `helm template` only, not on a cluster.

### OpenShift oauth-proxy sidecar (`oauthProxy`)

Puts the OpenShift `oauth-proxy` in front of Grafana. The users sign in with the OpenShift OAuth server, the proxy
checks a `SubjectAccessReview` (`--openshift-sar`) and passes the user name in the `X-Forwarded-User` header, which
Grafana trusts (`auth.proxy`, auto sign up). The sidecar is added to the generated `Grafana` spec next to the
`grafana` container, which is not redeclared. It cannot be combined with `oidc.enabled`, and it requires
`grafana.enabled` and `route.enabled`. The default is `enabled: false` and does not change the rendering.

| Key | Default | Description |
| --- | --- | --- |
| `enabled` | `false` | Add the sidecar, the `<grafana.name>-oauth-proxy` ServiceAccount, the `oauth-proxy` Service port with a serving certificate and a reencrypt Route targeting it |
| `image`, `port`, `upstream` | `image-registry.openshift-image-registry.svc:5000/openshift/oauth-proxy:v4.4`, `8443`, `http://localhost:3000` | Image, HTTPS port of the proxy and Grafana URL it forwards to |
| `serviceAccountName`, `tlsSecretName` | `<grafana.name>-oauth-proxy`, `<grafana.name>-oauth-tls` | ServiceAccount carrying the OAuth redirect reference (the route `<grafana.name>-route`) and Secret created by the service-ca operator |
| `sar.namespace`, `sar.resource`, `sar.verb` | project namespace, `pods`, `get` | Only the users allowed by this `SubjectAccessReview` can sign in. Other keys set under `sar` are added to it |
| `emailDomain`, `args`, `resources` | `*`, `[]`, `{}` | `--email-domain`, additional arguments and resources of the proxy container |
| `authProxy.disableLoginForm`, `authProxy.whitelist` | `true`, `127.0.0.1,::1` | Grafana `auth.proxy` settings. Both loopback families are needed because `localhost` can resolve to `::1` |
| `cookieSecret.enabled`, `name`, `value` | `true`, `<grafana.name>-oauth-cookie`, `""` | Secret holding the cookie secret (key `cookie_secret`, 16, 24 or 32 bytes). `value` is required unless `externalSecret` is used |
| `cookieSecret.externalSecret` | disabled | Produce the Secret with the External Secrets Operator (`remoteRefs.cookie_secret`) |

The Grafana data is kept in an `emptyDir` unless you add a `persistentVolumeClaim` to `grafana.spec`. With a
ReadWriteOnce volume, also set `deployment.spec.strategy.type: Recreate` in `grafana.spec`, otherwise the new pod
fails with `index is locked by another process` during a rolling update. A list set in `grafana.spec` replaces the generated one, so a `volumes` override must also declare the `oauth-tls` volume (secret `<grafana.name>-oauth-tls`). The configuration comes from a Grafana
deployment validated with grafana-operator 5.24 and 5.25. The templates of this chart were checked with `helm template`
only: validate them on a cluster before relying on them.

### OpenID Connect authentication (`oidc`)

| Key | Default | Description |
| --- | --- | --- |
| `enabled` | `false` | Configure the Grafana `generic_oauth` authentication. Requires `grafana.enabled`, `route.enabled` and `route.host` |
| `name` | `OpenID Connect` | Label of the login button |
| `issuerUrl` | `""` | Issuer of a Keycloak realm (`https://<keycloak host>/realms/<realm>`). The endpoints not given below are derived from it with the Keycloak layout (`<issuerUrl>/protocol/openid-connect/...`) |
| `authUrl` | `""` | Authorization endpoint. Required when `issuerUrl` is empty |
| `tokenUrl` | `""` | Token endpoint. Required when `issuerUrl` is empty |
| `apiUrl` | `""` | Userinfo endpoint. Required when `issuerUrl` is empty |
| `signoutUrl` | `""` | Logout endpoint, used as is (the chart adds no parameter). Empty with an empty `issuerUrl`: Grafana only logs out locally |
| `clientId`, `scopes` | `grafana`, `openid email profile` | Client registered in the provider and requested scopes |
| `roleAttributePath` | `grafanaadmin`, `admin`, `editor` roles, else `Viewer` | JMESPath expression mapping the claims of the user to a Grafana role. The default reads a top-level `roles` claim |
| `clientSecret.enabled`, `name`, `value` | `true`, `<grafana.name>-oidc-client`, `""` | Secret holding the client secret (key `client-secret`). `value` is required unless `externalSecret` is used |
| `clientSecret.externalSecret.enabled`, `remoteRefs` | `false`, `{}` | Produce the Secret with an `ExternalSecret` instead (key `client-secret` required) |
| `ca.certificate` | `""` | Inline PEM CA certificate(s) of the provider endpoints, rendered in the ConfigMap `<grafana.name>-oidc-ca` |
| `ca.injectTrustedBundle` | `false` | Inject the cluster trusted CA bundle (system CAs and proxy `trustedCA`) in the ConfigMap `<grafana.name>-oidc-ca` |
| `ca.configMap`, `ca.key` | `""`, `ca-bundle.crt` | Existing ConfigMap holding the CA bundle, and its key. `ca.key` is ignored with `ca.injectTrustedBundle`, which always uses `ca-bundle.crt` |

The endpoints come from two modes, which can be mixed:

- **Keycloak issuer**: set `issuerUrl` only. The chart derives the endpoints from it: `/auth`, `/token`, `/userinfo`,
  and `/logout` with the `post_logout_redirect_uri` and `client_id` parameters (single logout).
- **Explicit URLs**: set `authUrl`, `tokenUrl` and `apiUrl`, and optionally `signoutUrl`, for any OpenID Connect
  provider. Take them from the discovery document of the provider (`.well-known/openid-configuration`:
  `authorization_endpoint`, `token_endpoint`, `userinfo_endpoint`, `end_session_endpoint`). With an `issuerUrl` as
  well, each URL given replaces only its own derived endpoint.

With `oidc.enabled`, the rendering fails when `issuerUrl` is empty and one of `authUrl`, `tokenUrl` or `apiUrl` is
missing. It also fails when more than one CA source is set: `ca.certificate`, `ca.injectTrustedBundle` and
`ca.configMap` are mutually exclusive.

The generated `generic_oauth` section also sets `login_attribute_path: preferred_username`, `email_attribute_path: email`,
`name_attribute_path: name`, `use_pkce: true`, `allow_assign_grafana_admin: true` and `allow_sign_up: true` (every user
of the provider gets a Grafana account at the first login). Any of them can be overridden in `grafana.spec`
(`config.auth.generic_oauth`), for instance when the provider does not send `preferred_username`.

## Procedures

### Grafana access

```bash
# URL of grafana
echo "https://$(oc get route startx-route -n default-grafana -o jsonpath='{.spec.host}')/"
# admin credentials generated by the operator (grafana.adminSecret disabled)
oc get secret startx-admin-credentials -n default-grafana -o jsonpath='{.data.GF_SECURITY_ADMIN_USER}' | base64 -d; echo
oc get secret startx-admin-credentials -n default-grafana -o jsonpath='{.data.GF_SECURITY_ADMIN_PASSWORD}' | base64 -d; echo
```

The local admin account stays available next to the OpenID Connect login, as a break glass account.

### OpenID Connect with cluster-rhbk

1. Deploy `cluster-rhbk` with its `values-startx_noinfra-grafana.yaml` values. The startx realm then gets a confidential
   `grafana` client, its client roles (`grafanaadmin`, `admin`, `editor`, `viewer`) and a mapper that copies them into a
   top-level `roles` claim.
2. Deploy this chart with the `values-startx_noinfra-rhbk.yaml` values. In both files, replace `apps.example.com` with the
   apps domain of the cluster, and use the same client secret (`oidc.clientSecret` here, `rhbk_realms.secrets` in cluster-rhbk).
3. Make Grafana trust the CA of the Keycloak route. When the ingress certificate is signed by a CA of the proxy
   `trustedCA` (enterprise PKI), `oidc.ca.injectTrustedBundle: true` is enough. With the default self-signed ingress
   certificate of OpenShift, give its CA inline instead (commands below). Set only one CA source: the chart rejects
   `oidc.ca.certificate`, `oidc.ca.injectTrustedBundle` and `oidc.ca.configMap` together.
4. Assign the client roles of `grafana` to the users in Keycloak. A user without any role logs in as `Viewer`.

```bash
# CA of the default ingress certificate of OpenShift, given inline to the chart
oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}' > ingress-ca.crt
helm upgrade ... --set oidc.ca.injectTrustedBundle=false --set-file oidc.ca.certificate=ingress-ca.crt
```

With `oidc.ca.injectTrustedBundle`, OpenShift writes the bundle into the ConfigMap after it is created, so its `/data`
must be ignored in the Argo CD Application (see the examples).

### OpenID Connect with another provider

1. Register a confidential client in the provider (for example SimpleSAMLphp with its OpenID Connect module), with
   `https://<route.host>/login/generic_oauth` as redirect URI and, for the single logout, `https://<route.host>/login`
   as post logout redirect URI.
2. Read the endpoints from the discovery document of the provider, and set them in `oidc.authUrl`, `oidc.tokenUrl`,
   `oidc.apiUrl` and `oidc.signoutUrl`. Leave `oidc.issuerUrl` empty.
3. Adapt `oidc.roleAttributePath` and `oidc.scopes` to the claims of the provider (see below).
4. Make Grafana trust the CA of the provider endpoints with one of the `oidc.ca` sources, as for Keycloak.

```bash
curl -s https://idp.example.com/.well-known/openid-configuration | jq '{authorization_endpoint, token_endpoint, userinfo_endpoint, end_session_endpoint}'
```

```yaml
route:
  enabled: true
  host: grafana.apps.example.com
oidc:
  enabled: true
  name: Company SSO
  issuerUrl: ""
  authUrl: https://idp.example.com/oidc/authorize
  tokenUrl: https://idp.example.com/oidc/token
  apiUrl: https://idp.example.com/oidc/userinfo
  signoutUrl: https://idp.example.com/oidc/logout?post_logout_redirect_uri=https%3A%2F%2Fgrafana.apps.example.com%2Flogin&client_id=grafana
  clientId: grafana
  scopes: openid email profile roles
  roleAttributePath: "contains(roles[*], 'grafana-admin') && 'GrafanaAdmin' || contains(roles[*], 'admin') && 'Admin' || 'Viewer'"
  clientSecret:
    value: "<path:kv/data/grafana/oidc#client_secret>"
  ca:
    injectTrustedBundle: true
```

The URLs above are placeholders: the paths depend on the provider and its version. `signoutUrl` is used as is, so add
the parameters the logout endpoint of the provider expects, such as `post_logout_redirect_uri` and `client_id`. Grafana
adds the `id_token_hint` parameter itself.

`roleAttributePath` must follow the claims the provider really sends. The default expression reads a top-level `roles`
claim filled by the `cluster-rhbk` mapper, which other providers do not send: without a matching claim, every user logs
in as `Viewer`. Check the claims of a test user first, and request the scope that releases them in `oidc.scopes`.

Some providers only return the claims in the userinfo response. With SimpleSAMLphp, attributes become claims through
its translate table, and a custom claim has to belong to a private scope, such as the `roles` scope of the example
above. `oidc.apiUrl` is then essential. Grafana keeps the first valid role, from the ID token, then from the userinfo
response: do not guard the claim with a default such as ``roles || `[]` ``, otherwise the expression already returns
`Viewer` on the ID token and the userinfo response is never read.

### Operator update

The subscription uses a manual install plan approval and a `startingCSV` (`operator.subscription.version`) that only
pins the first installation. To upgrade, approve the pending install plan, then align `operator.subscription.version`.
As long as `grafana.version` is set, the Grafana version does not change with the operator.

```bash
oc get installplan -n default-grafana
oc patch installplan <name> -n default-grafana --type merge -p '{"spec":{"approved":true}}'
```

## Deploy with ArgoCD

### AppProject

```bash
git clone https://gitlab.com/startx1/helm.git
cd helm-repository/charts/cluster-grafana/examples/argocd/
oc apply -k .
```

### Applications

The `examples/argocd` folder holds the AppProject and the three Applications (project, operator, app) of the standard
pattern, using `values-startx_noinfra.yaml`.

| Application                | Wave   | Enabled flags                                                                                         | Destination       |
| -------------------------- | ------ | ----------------------------------------------------------------------------------------------------- | ----------------- |
| `cluster-grafana-project`  | `"1"`  | `project.enabled: true`, all others `false`                                                           | `default-grafana` |
| `cluster-grafana-operator` | `"5"`  | `operator.enabled: true`, all others `false`                                                          | `default-grafana` |
| `cluster-grafana-app`      | `"10"` | `grafana`, `route`, `grafana_datasources`, `grafana_dashboards` enabled, `project`/`operator` `false` | `default-grafana` |

The `-operator` and `-app` Applications carry the `resources-finalizer.argocd.argoproj.io` finalizer, the `-project`
Application has none. `oidc.enabled` is not a wave flag: it only acts together with `grafana.enabled`. The first
install plan of the operator has to be approved (see Operator update) before `cluster-grafana-app` can sync. Delete the
Applications in reverse order (`-app`, then `-operator`, then `-project`) so that the operator deletes the objects it
generated before it is removed.
