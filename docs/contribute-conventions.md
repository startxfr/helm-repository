# Chart conventions

The rules every chart of this repository follows. They are the reference for authors and reviewers: `CLAUDE.md`
summarizes them for agents and links here, `.github/scripts/ci-check.sh` enforces the ones a script can check, and
`.claude/KNOWN_ISSUES.md` lists the charts that do not follow them yet.

Each rule is tagged with how it is enforced:

- **[CI]** checked by `.github/scripts/ci-check.sh`, a failure blocks the merge
- **[CI-report]** checked by `ci-check.sh conventions`, reported but not blocking until every chart complies
- **[review]** checked by the reviewer before a release

Exceptions are listed in [Exceptions](#exceptions); a chart is never exempted silently.

## 1. Files of a chart

```
charts/<name>/
  Chart.yaml  values.yaml  values.schema.json  README.md  .helmignore
  values-startx*.yaml              alternative values files, optional
  examples/argocd/                 AppProject + Applications + kustomization.yaml (see section 6)
  templates/_helpers.tpl  templates/_startx.tpl  templates/NOTES.txt  templates/*.yaml
```

- `Chart.lock` and `charts/<name>/charts/` are generated and never tracked (ADR-0005). **[CI]** (`.gitignore`)
- `docs/charts/<name>.md` is a byte-for-byte copy of `charts/<name>/README.md`, committed with it. **[CI]**
- Every new chart also gets `charts/cluster-argocd/values-app-<name>.yaml` (section 6).

## 2. Chart.yaml

| Field | Rule | Check |
| --- | --- | --- |
| `apiVersion` | `v2` | [CI-report] |
| `name` | the directory name | [CI] (`helm lint`) |
| `description` | one sentence that names the product the chart configures; no copy of another chart's description | [review] |
| `type` | `application` | [CI-report] |
| `version` | `MAJOR.MINOR.PATCH`, MAJOR aligned to the OpenShift minor (see [Release notes](contribute-releases.md)); set by the release tooling, never by hand | [review] |
| `appVersion` | the upstream version (operator CSV, image tag), quoted | [review] |
| `kubeVersion` | always set, as a lower bound (`">=1.30.0-0"`) | [CI-report] |
| `icon`, `home`, `sources`, `maintainers`, `keywords` | always set; `icon` points to `img/<name>.svg` | [CI-report] |
| `dependencies[].version` | exact pin: for a chart served by this bucket, the highest version already published of the same `MAJOR.MINOR`, strictly lower than the chart version (`.tools/bump-pins.py`, ADR-0006) | [CI] (`ci-check.sh static`, offline: pin < chart version) |
| `annotations."artifacthub.io/changes"` | describes this release; updated at each release | [review] |
| `annotations."artifacthub.io/prerelease"` | `"true"` or `"false"`, quoted | [CI-report] |
| `annotations."artifacthub.io/license"`, `category`, `signKey`, `containsSecurityUpdates` | always set | [CI-report] |

Every field keeps the one-line comment above it (`# Kube minimum version`, ...), as in the existing charts.

## 3. values.yaml

- The first line is `# Default values for <name>.` **[CI-report]**
- `context:` is the first top-level key, with the six keys `scope`, `cluster`, `environment`, `component`, `app`,
  `version`; `context.app` defaults to the chart name. **[CI-report]**
- Every top-level key has a comment line right above it. **[CI-report]**
- Every feature is behind an `<feature>.enabled` switch, and every switch turned on alone must render.
  **[CI]** (`ci-check.sh toggles`)
- A cluster singleton (OAuth, cluster monitoring, APIServer, ...) has its own switch, off by default when another
  chart may own it (ADR-0002). **[review]**
- No secret value in a committed values file: use an Argo CD Vault Plugin placeholder (`<path:...>`) or a values
  file kept out of Git. **[review]**
- Every `values-startx*.yaml` file must render (`helm template`) and validate against the schema. **[CI]**
- Operator namespaces follow the naming table of `CLAUDE.md` (*Operator namespace naming rules*). **[review]**

## 4. values.schema.json

Policy in ADR-0003, summarized:

- The chart's own properties are generated by `make schema CHART=<name>`; the dependency and context blocks are
  generated by `.tools/schema-sync.py <name>` (local `$defs`, never a `$ref` to `raw.githubusercontent.com`). Both are
  committed in the same commit as the `values.yaml` change.
- `ci-check.sh schema`: no key of `values.yaml` may be missing from the schema (it looks 2 levels deep only). **[CI]**
- `schema-sync.py --check <name>` reports 0 outdated, and `grep raw.githubusercontent charts/<name>/values.schema.json`
  is empty. **[CI-report]** until it is wired in `ci-check.sh`, then **[CI]**.
- Valid JSON; validates the default values and every `values-startx*.yaml`. **[CI]**
- A hand-written schema is an exception listed in `.claude/KNOWN_ISSUES.md`; `make schema` is never run on it.
- Free-form blocks handed to an operator (a custom resource `spec`) stay open.

## 5. README.md

The README is the user documentation of the chart: it is published on readthedocs (`docs/charts/<name>.md`) and on
Artifact Hub. It is written in English for a reader who does not know this repository.

### 5.1 Header

```markdown
# ![<name>](https://helm-repository.readthedocs.io/en/latest/img/<name>.svg "<Family> Chart : <Product>") <Family> Chart : <Product>
[![Artifacthub](https://img.shields.io/badge/ArtifactHub-STARTX_<name with -- for ->-8A2BE2.svg)](https://artifacthub.io/packages/search?ts_query_web=<words>+startx)

<Description: what the chart deploys and for whom, in one or two paragraphs. Never the placeholder
"This helm chart must have a description".>
```

### 5.2 Sections

The `##` sections appear in this order. Mandatory sections are always present; optional ones are present only when
they have content, and then at their place in the order. Use the exact titles below. **[CI-report]** (`ci-check.sh conventions` checks the order of the known titles, the titles in the table of old titles below, duplicate titles, the mandatory sections, `## History` last, and that every `values-*.yaml` of the chart is named in `## Values files` or matched by a glob written there; sections not listed in the table are chart-specific and free)

| # | Section title | Presence | Content |
| --- | --- | --- | --- |
| 1 | `## Requirements and guidelines` | mandatory | OpenShift and operator prerequisites, cluster-admin needs, links to the requirement charts |
| 2 | `## What the chart renders` | optional | the resources the chart creates, with the switch of each |
| 3 | `## Deploy this helm chart on openshift` | mandatory | four `###` steps: *1. Connect to your Openshift cluster*, *2. Install the repository*, *3. Get information about this chart*, *4. Install this chart*; the repository URL is `stable` (never `noschema`) |
| 4 | `## Deploy this helm chart on kubernetes` | optional | only for a chart that supports plain Kubernetes |
| 5 | `## Default values` | mandatory | what `values.yaml` deploys, as a list of resources with their key settings. The `example-*`, `operator`, `project` and `sxapi` charts describe `values.yaml` as the first entry of `## Values files` instead, which is accepted |
| 6 | `## Values files` | mandatory in every README | describes the example files of the chart: one entry per `values-*.yaml` (name, what it deploys, raw GitHub link) or per glob (`values-startx_noinfra*.yaml`) covering several files, plus the `examples/` directories; one `helm install ... -f` example. Placed right after `## Default values` (else after the `Deploy this helm chart on ...` sections), always before `## Values dictionary`. **[CI-report]** every `values-*.yaml` of the chart is named or covered by a glob |
| 7 | `## Values dictionary` | optional | tables `Key / Default / Description`, one `###` per top-level key. Once `.tools/readme-values.py` exists the tables sit between `<!-- values:start -->` and `<!-- values:end -->` markers: generated, never edited by hand, checked by `--check` in CI. A key table inside `## Default values` is accepted in place of this section |
| 8 | *chart-specific sections* | optional | any topic of the chart (`## Cluster monitoring`, `## Ownership of the cluster singletons`, ...) |
| 9 | `## Procedures` | optional | day-2 operations: manual backup, rotation, migration, upgrade notes |
| 10 | `## Usage examples` | mandatory for `chaos-*`, optional elsewhere | at least three examples for `chaos-*`: default/full stack, minimal, advanced |
| 11 | `## Deploy with ArgoCD` | mandatory for every chart with `examples/argocd/` and every `cluster-*` chart | see 5.3 |
| 12 | `## External secrets` | optional | Vault paths and Argo CD Vault Plugin placeholders the Applications expect |
| 13 | `## History` | mandatory, always last | see 5.4 |

Titles not to use any more, and their replacement:

| Old title | Use |
| --- | --- |
| `ArgoCD deployment`, `Deploy this helm chart with ArgoCD`, `Install with ArgoCD`, `Deploy via ArgoCD` | `Deploy with ArgoCD` |
| `Values`, `Values overview` | `Values dictionary` |
| `Resources rendered` | `What the chart renders` |
| `Others values availables`, `Other available values` | `Values files` |

### 5.3 Deploy with ArgoCD

- One section only (never two ArgoCD sections in the same README).
- It describes the AppProject and the Applications of `examples/argocd/` (by default `-project` wave 1, `-operator`
  wave 5, `-app` wave 10) and how to apply them, in the form used by 72 READMEs: `git clone` the repository, `cd helm-repository/charts/<name>/examples/argocd/`, `oc apply -k .`.
- Helm sources use the range `targetRevision: 21.3.x` in the examples, with a sentence telling production users to
  pin an exact version (ADR-0004). **[CI]** (`ci-check.sh argocd`)
- The full pattern (flags set to `false` in every Application, finalizers, deletion order, `ignoreDifferences`,
  sync waves) is in `CLAUDE.md`, *ArgoCD deployment pattern*. **[review]**

### 5.4 History

- `## History` is the last section; with several tables (`cluster-acm`, `sxapi`) the active table is the last one.
- Columns `Release | Date | Description`; one separator row per table; every row ends with `|`. **[CI-report]**
- Rows are added and pruned by the release tooling (`.tools/history-prune.py`); never edit or reorder existing rows
  by hand, except to fix a typo or a duplicated row.

## 6. ArgoCD deliverables

For every `cluster-*` chart (and every chart with an ArgoCD section):

| Deliverable | Rule | Check |
| --- | --- | --- |
| `charts/<name>/examples/argocd/` | `appproject.yaml`, `kustomization.yaml` and one `application-<wave>.yaml` per wave the chart has: `-project`, `-operator`, `-app` by default; a chart without operator or namespace skips that wave, a chart split by feature uses one file per feature (`application-monitoring.yaml`, ...) | [review] |
| | every file parses | [CI] |
| | `kustomization.yaml` lists every file of the directory, `appproject.yaml` included | [CI-report] |
| | the `spec.project` of every Application is the AppProject defined in the same directory | [CI-report] |
| `charts/cluster-argocd/values-app-<name>.yaml` | generated by `.tools/generate-values-app.py`; renders with `cluster-argocd`; every Application has a `repoURL`, a destination namespace and an explicit revision | [CI] (`ci-check.sh argocd`) |
| `## Deploy with ArgoCD` in the README | section 5.3 | [CI-report] |
| `CLAUDE.md` list *Charts with ArgoCD examples* | the chart is listed | [review] |

Naming: AppProject `infra-<name>` for `cluster-*`, `chaos-<name>` for `chaos-*`, `app-<name>` for `example-*`;
Applications add `-project`, `-operator`, `-app` (details in `CLAUDE.md`, *cluster-argocd values-app pattern*). A chart
with a single workload wave may use `-instance` (12 examples today: `chaos-*`, `chaos-pipeline`); `.tools/generate-values-app.py`
derives the `values-app-*` names from the example files, so renaming an example means regenerating its `values-app-*` file.
A chart split by feature uses one suffix per feature (`-monitoring`, `-registry`, ...).

## 7. Writing

- English only, in code, comments, values, READMEs, commits and docs.
- The misspellings of `CLAUDE.md` (*Recurring misspellings*) are rejected in the whole tree. **[CI]**
- Product names: OpenShift, ArgoCD, Kubernetes, Helm (Artifact Hub badge text excepted).

## 8. Commits and releases

- Commit subjects: `[chart/<name>] <verb>: <description>`, `[docs] <description>`, `[tools] <description>`.
- A chart change commits together: templates, `values.yaml`, `values.schema.json`, README and `docs/charts/<name>.md`.
- Only the charts that changed are released (ADR-0001); only the repository lead releases, publishes, tags and pushes (ADR-0004).
- A change to a chart a consumer uses is announced before the push and its rendered manifests are compared with the
  last tag (`.tools/render-compare.sh`, ADR-0004). Consumed charts: `operator`, `project`, `cluster-rbac`,
  `cluster-ods`, `cluster-istio`, `cluster-prometheus`, `cluster-certmanager`, `cluster-gpu`, `cluster-machine`,
  `cluster-nfd` (pinned versions in `.tools/consumer-pins.txt`).
- Roles: the author changes a chart, the reviewer checks it, the repository lead releases it, and the projects that
  consume the charts are listed in ADR-0004. Review findings go to the author of the change, blocking ones also to
  the repository lead; a request from a consumer project goes through the repository lead.
- A change that claims to keep the render unchanged shows zero diff in `.tools/render-golden.py`. **[review]**

## 9. Before asking for a release

Run, from the repository root, on the charts you changed:

```bash
.github/scripts/ci-check.sh static
.github/scripts/ci-check.sh schema
.github/scripts/ci-check.sh charts "<name> ..."
.github/scripts/ci-check.sh toggles <name> ...
.github/scripts/ci-check.sh argocd            # when examples/argocd or a values-app file changed
.github/scripts/ci-check.sh conventions       # report only for now
tests/contract/run.sh                         # when a consumed chart changed
```

then send the list of changed charts and the results to the reviewer.

## 10. Charts wrapping an upstream project (chaos-*, cluster-*)

Lessons of the chaos releases 21.3.391 and 21.3.392; each rule was a defect found in review.

- **Read the upstream source at the pinned version**, not the website: the configuration reference is the upstream
  `config/` of the tag (or of the image). Every rendered key must exist upstream.
- **Schemas are local.** No `$ref` to `raw.githubusercontent.com`: run `.tools/schema-sync.py <chart>` and commit its
  output; `schema-sync.py --check <chart>` must report 0 outdated. Renders must work without network access.
- **Names that the chart does not own must follow the upstream naming rule** (fullname helper, `nameOverride`,
  alias as chart name). Test several release names and the empty `fullnameOverride` / `nameOverride` cases whenever
  a template derives a service account, secret or service name from them.
- **Anything an upstream chart generates at each render (genCA, random passwords, `rollme` annotations) needs
  `ignoreDifferences` + `RespectIgnoreDifferences=true` in the ArgoCD examples and in the `values-app-*` file.**
  Umbrella and standalone examples must stay identical on this point.
- **No literal credential in values or examples**: empty default, `existingSecret`, and a `fail` with a clear message
  when a required secret is missing. A toggle that cannot render alone is declared in `render-golden.py`
  (`TOGGLE_NEEDS_VALUES`).
- **Rights follow the enabled features**: privileged helper pods, cluster-wide bindings and custom SCC copies are
  rendered only when an enabled scenario needs them; prefer binding `system:openshift:scc:privileged` to a custom
  SCC. Check the namespace in which upstream creates its workload pods (it can be hard-coded, e.g. `default`).
- **A switch must do what its description says**: if it needs an extra right or a value to work, say so in values.yaml
  and the README (example: `checkCriticalAlerts` needs a token on `prometheus-k8s`).
- **Examples are tested like code**: `ci-check.sh argocd`, `oc apply --dry-run=server` on a cluster with the CRDs
  (authorization of the cluster owner required), kustomize build.
- **Commit messages and release notes must match the tree**: verify claims such as "schemas embedded" with a grep.
- **Render every values file and count the objects**, not only lint: a `values-startx-deploy.yaml` with `enabled: false`
  rendered nothing.
- **Every name a template hardcodes (Route target, Service, ServiceAccount) must exist in the render of the sub-chart**
  (`ui` instead of `chaos-dashboard`).
- **Example values are checked against the upstream `values.yaml`**: a Helm render does not complain about a misspelled
  key (`timezone` vs `timeZone`).
- **A key read by a template (`.Values.x.y`) must exist in `values.yaml` and in the schema** (`litmus.expose` was
  missing): grep the templates against both.
- **Every `valueFiles` entry of an ArgoCD example must exist in the chart directory** (3 charts and the umbrella pointed
  to a missing `values-startx_noinfra.yaml`). **[CI-report]** to add to `ci-check.sh argocd`.
- **A `## ` heading is preceded by a blank line** (generated READMEs lost it). **[CI-report]**
- **Internal pins** (ADR-0006): the pin of a dependency is never the version of the chart that carries it, only a version
  already published below it; a dependency that changed reaches its dependents when they are released again.
  `release-verify.sh` checks that each pin is lower than the release and served.
